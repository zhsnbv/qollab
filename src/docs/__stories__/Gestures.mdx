# Жесты и клавиатура

## Потягивание для обновления

`TabLayout` даёт его всем вкладкам сразу — Главной, Ленте, Чатам, Сервисам,
Профилю. Контент тянем сами, а не «резинкой» браузера: только так сверху видна
белая подложка со спиннером, а не серый фон приложения.

- срабатывание — 62px
- удержание во время загрузки — 54px
- дальше 92px контент не уходит
- минимум 700 мс, даже если данные готовы

Слушатели вешаются с `{ passive: false }`: без этого `preventDefault` на
`touchmove` не сработает и страница уедет вместе с жестом.

## Свайп по сообщению

Вправо — ответ. Порог 48px, максимум 72px, сопротивление 0.6 — дальше палец
двигает бабл медленнее, чем сам движется, и жест ощущается упругим.

## Свайп по листу

Вниз — закрыть. Закрывает 96px пути **или** скорость 0.5px/мс: короткий резкий
свайп — такое же намерение, как долгое перетаскивание.

Обработчики раздаёт `useSheetSwipe`, а вешает их `SheetTop` — свайп ловится
за шапку, чтобы не конфликтовать с прокруткой содержимого.

## Вертикаль не перехватываем

Общее для всех трёх жестов: если `|dy| > |dx|`, движение отдаётся браузеру.
Иначе список перестаёт прокручиваться там, где есть свайп.

## Клавиатура

`useViewportFit` держит на `<html>` переменные `--vvh`, `--vvtop`, `--kb`
и класс `.kb`.

Высота клавиатуры считается от **максимальной наблюдаемой** высоты окна:

```js
maxHeight = Math.max(maxHeight, vv.height);
const kb = Math.max(0, maxHeight - vv.height);
```

Очевидный способ — `innerHeight - visualViewport.height` — здесь всегда даёт
ноль: в теге viewport стоит `interactive-widget=resizes-content`, окно само
сжимается под клавиатуру. Из-за этого между полем ввода и клавиатурой держался
зазор высотой ровно с клавиатуру.

## Почему поле ввода — не `<input>`

Системную панель iOS со стрелками и «Готово» из веба убрать нельзя: она
вешается на любой элемент формы, и в PWA тоже. Поэтому `ComposeInput` сделан
на `contenteditable` — панель не появляется, а плейсхолдер, отправка по Enter
и вставка чистым текстом дописаны руками.
