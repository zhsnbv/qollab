# Навигация оверлеями

Вкладки живут в первом `Routes`, всё остальное открывается поверх. Экран, из
которого ушли, передаётся в `state.background`:

```jsx
navigate('/person', { state: { id, background: location } });
```

Передаём **текущий** `location`, а не свой `background`. Иначе под профилем
окажется список чатов вместо чата, из которого его открыли.

**`background` обязателен у каждого перехода на оверлейный роут.** Без него
под верхним экраном не рендерится ничего: вкладка размонтируется и при
возврате въезжает заново — экран «скачет». Проверять это стоит не глазами,
а тем, остался ли нижний экран в DOM.

## Цепочка разворачивается целиком

Из чата открыт профиль группы, из него — профиль участника. Под верхним экраном
должны остаться оба нижних:

```jsx
const underOverlays = [];
let root = background;
while (root && !TAB_ROUTES.includes(root.pathname)) {
  underOverlays.unshift(root);
  root = root.state?.background;
}
```

Пока цикл разворачивал цепочку на один шаг, экраны размонтировались и при
возврате въезжали заново — переход мигал.

## Оверлей перекрывает всё

Лист снизу и затемнение монтируются порталом в `.device`, а не в текущий
контейнер:

```jsx
createPortal(children, document.querySelector('.device'));
```

Причина конкретная: обёртка прокрутки вкладки стала позиционированным предком,
и лист оказывался **под** таб-баром. Портал возвращает его в общий слой —
затемнение накрывает и шапку, и таб-бар.

В Safari этого мало: `backdrop-filter` у таб-бара всплывает над затемнением
независимо от `z-index`. При открытом листе на `<html>` ставится `.scrim-open`,
фильтр гасится, таб-бару прописан `isolation: isolate`.

## Порядок блоков зависит от точки входа

Профиль коллеги одинаков, откуда бы ни открылся — иначе он не узнаётся.
Меняется ровно одно: при входе из чата блок переписки встаёт сразу под
действиями. Остальные блоки не двигаются.
