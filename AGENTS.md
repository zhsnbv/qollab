# Правила работы с прототипом qollab

## Перед изменением настроек или тем чатов

Прочитайте [руководство по темам](docs/chat-themes-guide.md). Состояния, ограничения прототипа, сценарии проверки и данные последнего выпуска находятся в [передаче разработчикам](docs/chat-themes-handoff.md). Исторические решения — в [журнале редизайна](docs/settings-redesign.md); при расхождении ориентируйтесь на актуальный исходный код и последние указания пользователя.

Эти правила относятся к настройкам и темам чатов. Они не требуют переделывать другие разделы приложения. Новое прямое указание пользователя имеет приоритет.

## Обязательные инварианты

- Канонический каталог — `src/utils/chatThemeCatalog.js`. Тема неделима: фон, входящий/исходящий бабл, текст и цвет статуса прочтения внутри бабла для светлого/тёмного режима. Не возвращайте произвольные цвета, независимые обои или переключатель паттерна без нового запроса пользователя.
- Сохраняется только `{ preset: id }` внутри `chatAppearance[companyId]`. ERG и Integra независимы. Не меняйте стабильные ID без миграции. Путь нового ассета меняйте через канонический poster, сохраняя прежний ID, как live-lake → live-steppe.webp. Не расширяйте устаревшие `WALLPAPERS`/`BUBBLE_COLORS` как новый UI-каталог.
- Стандартная тема получает цвета рабочего пространства из токенов. Тема чата не перекрашивает приложение, top bar или брендовые кнопки.
- Каталог — одна общая белая секция с предпросмотром и непрерывной адаптивной вертикальной сеткой. Плитки 9:16; без отдельных групповых карточек и горизонтальных лент. Выделение плитки — одна обводка. Live-маркер компактный, слева сверху; без видео честно показывается «LIVE · фото».
- Используйте общие `ChatWallpaper`, `Message`, `MessageReactions` и `MobileMessageMenu`. Не рисуйте отдельную имитацию баблов, статусов, реакций или long tap для настроек. Контекст выбранной темы переносится только в поднятую копию бабла. Панели меню, список прочитавших и список чатов используют цвета приложения/пространства (`MessageDeliveryStatus scope="app"`), а не read-цвет пресета.
- Не задавайте всем SVG одинаковый цвет: нейтральные состояния отправки и тематический статус прочтения имеют разную семантику. Время и receipt всегда находятся внутри бабла, включая фото, видео, голос, документ, профиль и ссылку; отдельные внешние строки времени не добавляются.
- Сохраняйте существующую шапку/фон настроек. Профиль не дублируется. Язык — bottom sheet, Қазақша первым. Залитые основные кнопки имеют `var(--radius-pill)`; текстовые строки подтверждения не превращаются в кнопки.
- Три миниатюры темы приложения (light/dark/system) имеют одинаковые пропорции 9:16, равные отступы и интервалы. Системная миниатюра не получает внутренних белых полос.
- Быстрая реакция — курируемый набор 40 эмодзи без поиска; свёрнуто 8, текущий выбранный виден всегда. Кнопка раскрытия имеет aria-expanded/aria-controls, шеврон вниз/вверх соответствует состоянию. Это не статистика рабочего пространства и не рейтинг 2026 года.
- `live-lake` — стабильный ID темы «Ночная степь»; актуальный poster — `live-steppe.webp`. Не возвращайте озеро и не сбрасывайте сохранённый ID. Пять градиентных тем используют пять разных grain SVG.
- Очистка кэша — полноэкранный слой внутри DeviceHost через Portal, сильное размытие/затемнение, эффекты в цветах пространства. Сохраняйте focus trap/restore, inert-фон и reduced motion; не возвращайте компактную карточку и фиксированную сине-фиолетовую палитру.
- Live-видео подключается только после получения и проверки настоящего 10-секундного клипа. Постер нельзя выдавать за анимацию или заменять движением CSS. Учитывайте reduced motion, скрытую вкладку, ошибку загрузки и отказ autoplay.
- После изменения каталога выполните модельные тесты и аудит цветов, проверьте реальный чат, long tap и компактную ширину. Для выпуска используйте `npm run build`: по умолчанию собираются приложение и Storybook в одном dist. `build:all` — alias этой команды; `build:app` собирает только приложение и не является полной публикационной сборкой. После завершения всех очередных деплоев проверьте активный deployment, приложение и настоящий iframe Storybook повторно; локальная сборка и кратковременный успех manual deploy не доказывают устойчивый выпуск.

## Процесс

Не затирайте параллельные изменения и не переносите весь грязный checkout в выпуск. Сначала проверяйте конкретный diff и рабочую копию. Не публикуйте без полномочий из текущего запроса; когда публикация уже поручена, не запрашивайте подтверждение повторно. Существующая площадка — Cloudflare Worker `qollab`, конфигурация `wrangler.jsonc`; новый проект для этого редизайна не нужен. Сохраняйте явный HTML handling, но не считайте его исправлением конкурирующих публикаций: другой выпуск с app-only dist уже заменял полный пакет. Источник такой публикации/CI нельзя придумывать без подтверждения.

Команды и критерии приёмки приведены в руководстве. Проверяйте актуальные npm scripts и исходники перед использованием исторических записей. При передаче сессии обновляйте технический handoff, явно разделяя выполненные проверки, ограничения и ещё не полученные материалы.
