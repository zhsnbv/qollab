# Повторная обработка трёх видео пользователя

Переносимый рецепт для «Прибой», «Призма» и «Маки». Исходные видео в эту папку и Git не входят. Их имена, SHA256 и выбранные параметры записаны в manifest.json. Скрипт читает оригиналы, не изменяя их. Результаты пишет только в явно указанную папку, не устанавливая их автоматически в приложение.

Нужны Python 3.9+, ffmpeg/ffprobe с libx264 в PATH, NumPy и Pillow с WebP. Зависимости: `python3 -m pip install -r requirements.txt` в выбранном виртуальном окружении.

Из корня проекта, сначала проверить источники:

```sh
python3 scripts/chat-wallpapers-v11/supplied/process.py --input-dir /path/to/originals --verify-only
```

Пересобрать все три клипа в отдельную папку:

```sh
python3 scripts/chat-wallpapers-v11/supplied/process.py --input-dir /path/to/originals --output-dir /path/to/delivery
```

Переименованные файлы задаются через `--coast coast.mp4 --prism prism.mp4 --poppies poppies.mp4`. Допускаются абсолютные пути. Обработка поднабора: `--only prism`. По умолчанию существующие outputs не затираются; `--overwrite` разрешает заменить их, но никогда оригинал. `--keep-master` сохраняет крупные lossless-мастера; по умолчанию они временные. `--skip-metrics` пропускает дорогие SSIM/PSNR/temporal-измерения, но сохраняет проверку полного декодирования. `--allow-source-change` нужен только для осознанной замены исходника: геометрия 1080×1920, 24 fps и 240 кадров всё равно проверяются.

Результат: `video/*.mp4`, `posters/*.webp`, manifest.json и QA-логи. Каждый клип — 9 секунд, 720×1280, 24 fps, без звука, H.264 High/yuv420p/faststart. Используется секундное смешивание конца с началом по smoothstep, без reverse и интерполяции кадров. Первый и последний кадры — I-frame. Постер совпадает с первым кадром. Для coast/poppies выбран CRF 26; для prism — 21.

SSIM/PSNR сравнивают обработанный lossless-мастер и output с точным выравниванием кадров. В manifest попадают native- и mobile-метрики, параметры и хеши. Результат сжат с потерями; метрики не заменяют просмотр нескольких повторов на целевом устройстве. На других версиях ffmpeg/x264/Pillow итоговые байты могут отличаться: поле runtime_matches_v11 показывает совпадение с проверенной поставкой, не объявляя иной хеш ошибкой качества.

Перед подключением результата убедитесь, что источники совпали, все кадры декодируются, стык не даёт заметного скачка, а реальные режимы reduced motion, скрытой вкладки и отказа autoplay сохраняют постер. Оригиналы, masters и промежуточные candidates не добавляйте в runtime-папки.
