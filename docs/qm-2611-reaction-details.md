## Проверка

- Интерактивный прототип: `/handoff/reaction-details`.
- Все 22 кадра: `/handoff/reaction-details?view=board`.
- Отдельный кадр 1440 × 900: `/handoff/reaction-details?view=frame&theme=light&state=menu`.
- Темы: `light`, `dark`. Состояния перечислены ниже.
- Правая кнопка мыши на сообщении или кнопка «···» открывает меню. Строка «Реакции: N» открывает список. Кнопка «Сбросить» восстанавливает выбранный сценарий.

## Решение по формату списка

Выбрано **модальное окно** шириной 440 px, с максимальной высотой 596 px. Окно располагается по центру веб-интерфейса, не меняет размеры чата и сохраняет контекст исходного сообщения. Это даёт достаточно места имени, времени и эмодзи и не зависит от положения сообщения у края окна.

В шапке — «Реакции», общее число и закрытие. Ниже — автор, дата/время и краткий текст исходного сообщения. Затем один плоский список: аватар 40 × 40, полное имя, время, эмодзи 24 px. Длинное имя переносится; при отсутствии фотографии остаются инициалы. Новые реакции сверху. Для длинного списка прокручивается только его содержимое, шапка остаётся на месте. Это выбранный порядок для прототипа; отдельного требования по сортировке в QM-2611 нет.

Закрытие: крестик, Esc, клик по затемнению. Фокус удерживается в окне и после закрытия возвращается к кнопке исходного сообщения. Поддерживается уменьшение анимации. Встраиваемый кадр всегда 1440 × 900; интерактивное превью автоматически масштабируется под ширину страницы.

## Меню и правила видимости

- Две отдельные строки одинаковой высоты 44 px над действиями сообщения.
- На своём сообщении: «Просмотров сообщения: N» для нескольких читателей; «Прочитано вчера в 16:35» для одного. Ниже «Реакции: N».
- На чужом сообщении: только «Реакции: N». Прочтения доступны только автору.
- N — количество записей реакций, не число разных эмодзи.
- При N = 0 строки «Реакции» нет. Пустое окно реакций не создаётся.
- Капсулы сообщений используют существующий `MessageReactions` через `Message` без изменения их исходников. Обычный клик ставит/снимает свою реакцию; другая реакция заменяет предыдущую свою. Список через капсулу не открывается.
- Шесть быстрых эмодзи и «+» используют существующие `REACTIONS` и `EmojiPicker`.

## Кадры, каждая строка в двух темах

| state | Содержание |
| --- | --- |
| `menu` | Своё сообщение: просмотры 3 + реакции 6 |
| `one-reader` | Своё сообщение: один читатель с временем + реакции 6 |
| `incoming` | Чужое сообщение: реакции 3, без прочтений |
| `list` | Плоский список из 6 реакций, разные эмодзи и даты |
| `single` | Компактное окно с одной реакцией |
| `long` | 24 реакции, внутренняя прокрутка, длинное имя |
| `no-reactions` | Контроль отсутствия строки при N = 0; меню с прочтениями |

## Границы реализации и следующая публикация

Это отдельный локальный review-route с демонстрационными данными. Данные Jira прочитаны; статус задачи и комментарии не менялись. Figma использована только для проверки целевой страницы, запись не выполнялась. Сетевого API реакций, интеграции в основной `/chats` и релиза пока нет. Остальные пункты контекстного меню показаны для визуального контекста; копирование работает, прочие действия выводят явное демо-уведомление. Остальная структура lazy/Suspense и ветки publications уже существовали в незакоммиченной рабочей папке до начала QM-2611.

В рабочей папке есть многочисленные изменения других задач.
