# Qollab · передача анимации волн

## Что передать команде

Архив `qollab-call-waves.zip` содержит компонент из приложения, CSS, SVG-зерно, конфигурацию, JSON для других платформ и автономный `demo.html`. Сборщик: `node scripts/package-call-waves.mjs`. Файлы в архиве копируются из `src/calls/waves`, а не поддерживаются отдельно.

В `/all?group=calls` находятся 49 отдельных кейсов. Все экраны галереи имеют размер 402×820 без масштабирования. Тексты и пояснения для разработчика вынесены за рамку экрана. Настройки волн расположены внутри раздела звонков. По умолчанию движение остановлено, чтобы галерея не запускала десятки анимаций одновременно.

## React / Web

```jsx
import CallWave from './CallWave';

<div style={{ position: 'relative', isolation: 'isolate', overflow: 'hidden', background: 'var(--color-white)', width: 402, height: 820 }}>
  <CallWave status={call.status} quality="auto" paused={!isCallScreenVisible} />
  {/* UI звонка поверх волн */}
</div>
```

Передаются четыре свойства:

| Свойство | Значения | Ответственность |
|---|---|---|
| status | connecting, ringing, incoming, active, reconnecting, busy, declined, unanswered, unavailable, failed, ended, canceled, elsewhere | Авторитетное состояние из менеджера звонка |
| quality | auto, full, lite, static | Энергопотребление/возможности устройства |
| paused | boolean | Экран скрыт, приложение в фоне, галерея на паузе |
| palette | Внутреннее сопоставление в config.js | Не передавать свободные цвета из транспорта |

Компонент декоративный: не запрашивает микрофон, не управляет WebRTC, не запускает таймеры звонка. Переключайте `status` на существующем экземпляре, не меняя его React key: это сохраняет фазу и даёт плавный переход цвета.

`auto` выбирает lite при Save-Data, доступной памяти ≤4 GB или ≤4 логических потоках; иначе full. Это стартовая эвристика, а не измерение нагрева. При интеграции предпочтительно явно передавать режим из политики энергосбережения приложения.

## Цвета состояний

| Состояние | Цвет A | Цвет B |
|---|---|---|
| Подключение, вызов, входящий | #FAF4E9 | #FBEFE8 |
| Разговор | #E3FFF7 | #D3FEDA |
| Восстановление | #E7EEFF | #DED8FA |
| Занято, нет ответа, недоступен, отменён, завершён, ответили на другом устройстве | #F2F2F2 | #EBEFF6 |
| Отказ, ошибка | #FFECE3 | #FED3D3 |

Цвет меняется за 1400 ms. Завершённые состояния останавливают движение. При восстановлении движение замедлено до 13 s для дрейфа и 7 s для дыхания.

### Тёмная тема

Установите `data-theme="dark"` на родительском элементе (в приложении это `html`). Фон звонка берётся из токена поверхности, волны используют отдельную палитру `WAVE_DARK_PALETTES`. JSON версии 2 содержит `palettes` и `darkPalettes`. Переключение темы доступно и в автономном примере.

| Палитра | Цвет A | Цвет B |
|---|---|---|
| warm | #57402F | #613829 |
| active | #214C43 | #3B542F |
| quiet | #343536 | #313B48 |
| declined | #593830 | #643239 |
| reconnecting | #303F62 | #4A3B60 |

Световой слой в тёмной теме приглушён. Режимы full/lite/static поддерживают обе темы.

## Геометрия и время

Базовый экран: 402×820, координаты в логических пикселях. Все значения также находятся в `motion-spec.json`.

- Форма A: ширина экрана, высота 471, x −56, bottom −205.
- Форма B: ширина экрана, высота 471, x 104, bottom −269.
- Gaussian blur: σ 41,4 px. Не анимировать радиус blur.
- Маска: прозрачность 0 до 38% высоты, плавный переход к 1 на 65%.
- Дрейф A: 9 s, B: 11 s, ease-in-out, замкнутый цикл.
- Дыхание A: 4,8 s; B: 6,2 s, смещение −1,8 s. Cubic Bézier (0,45, 0, 0,35, 1).
- Масштаб дыхания: (0,94; 0,88) → (1,12; 1,30) → исходный. Центр (50%; 85%).
- Прозрачность дыхания: 0,82 → 1 → 0,82.
- Световой слой: 8 s; только в full.
- Зерно: статичный SVG, opacity 0,035; только в full. Шум не генерируется каждый кадр.

## Flutter / React Native / native

Это спецификация переноса, не готовый нативный пакет. CSS нельзя напрямую вставить в SwiftUI или Compose.

1. Создать две независимые группы: внешний transform для дрейфа, внутренний для дыхания. Палитра и фаза отделены от состояния звонка.
2. Full: один раз отрисовать размытую форму в текстуру/слой, затем двигать и масштабировать её. Проверить, что runtime не пересчитывает blur на каждом кадре.
3. Lite: две мягкие радиальные градиентные текстуры без blur, зерна, blend-mode и светового слоя. Движение остаётся тем же.
4. Остановить ticks при скрытом экране/свёрнутом приложении, reduced motion и терминальном состоянии. Не держать отдельную анимацию за миниатюрой.
5. Смену цвета делать интерполяцией или кроссфейдом двух заранее окрашенных слоёв за 1,4 s. Не пересоздавать весь эффект.
6. Входящий поверх блокировки отдавать системному UI платформы; карточка в `/all` — ориентир, а не обещание произвольного фона поверх lock screen.

## Контракт менеджера звонка

- `reconnecting`: отдельное состояние с дедлайном 15 s, сохранением session ID и исходного времени разговора. Повторные offline-события не продлевают дедлайн.
- На подтверждённом reconnect-success → active. На истечении дедлайна → failed. Перезагрузка должна восстанавливать серверный сеанс, а не создавать второй звонок.
- Локальная реализация сохраняет снимок сеанса в sessionStorage и воспроизводит восстановление при перезагрузке; ответы транспорта и уровень качества здесь управляются сценариями. Перед production подключить реальные события signaling/RTC.
- `unanswered` означает, что вызов был доставлен, но ответа нет. `unavailable` — вызов не удалось доставить. Не выводить «не разрешён микрофон» или «выключены уведомления» по одному тайм-ауту: нужна явная подтверждённая причина.
- Качество: `quality=good|poor`, `qualitySide=local|remote`. Метрики и сглаживание задаёт RTC-команда. UI показывает «Хорошее соединение», «Ваше соединение нестабильно», «Соединение собеседника нестабильно».
- Микрофон и камера: единый `PermissionSheet` с иконкой в круге; после отказа тот же лист предлагает настройки. Инструкция раскрывается внутри, без второго листа. `permissionAdapter.openSettings()` — точка интеграции native settings; без адаптера реальный переход в настройки ОС не выполняется. Демонстрация использует тот же визуальный паттерн и запускает системное подтверждение. На входящем экране две кнопки: «Принять» и «Отклонить». Второй входящий тоже полноэкранный, с пояснением и кнопками «Отклонить» / «Завершить и ответить».
- Исходящий busy/declined/unanswered/unavailable/failed: итог 2,6 s → уход экрана 340 ms → диалог причины с действиями «Написать в чат» / «Понятно». Отмена пользователем и отклонение входящего не создают диалог ошибки. Имена под терминальным статусом не дублируются.
- Busy: у вызывающего «Линия занята», у вызываемого пропущенный в переписке. Создание второй записи и синхронизацию между клиентами выполняет сервер; клиент не придумывает удалённую историю.
- Шапка получает данные собеседника отдельным объектом `person`. Для группового этапа заменить её на коллекцию участников, сохранив фон и нижние действия независимыми. Групповые сценарии сейчас не реализованы.

## Энергопотребление: что проверить на Android

Фактический нагрев здесь не измерялся. Он зависит от GPU, реализации blur, разрешения поверхности, видео, яркости и длительности звонка. Наличие transform-анимации само по себе не гарантирует низкую нагрузку.

На слабом, среднем и флагманском физическом устройстве сравнить full / lite / static: 10 минут аудио, затем 10 минут видео при одинаковой яркости. Снять frame time/jank, загрузку CPU/GPU, thermal status и расход батареи. Для 60 Hz ориентир кадра 16,67 ms; оценивать также p95, а не только среднее. При thermal warning или энергосбережении переключать lite/static. Reduced motion — static.

В web отключены повторяющиеся JS-кадры: анимация на CSS transform/opacity. Lite не использует runtime blur и декоративные дополнительные слои; скрытые/невидимые слои ставятся на паузу.

Источники для performance review: [web.dev — CSS animation performance](https://web.dev/articles/animations-guide), [Android — GPU rendering inspection](https://developer.android.com/topic/performance/rendering/inspect-gpu-rendering).

## Проверка поставки

`demo.html` открывается локально без сборки и сети. Меняйте состояние, режим full/lite/static и паузу. React-компонент проверяется в приложении. Скрипт `scripts/check-call-handoff.mjs` проверяет размеры, стабильность кейсов, баблы, disabled-действия и восстановление. `node --test src/calls/model.test.js` проверяет логику и движение миниатюры.
