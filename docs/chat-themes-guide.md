# Темы чатов qollab: руководство по изменению

Актуальный контракт редизайна v8, 17 ноября 2026. Документ предназначен разработчикам и AI-агентам. Статус проверки и публикации вынесен в [handoff](chat-themes-handoff.md): описание целевого поведения само по себе не означает, что оно проверено на устройстве.

## 1. Продуктовый контракт

Тема чата — готовая согласованная композиция: фон, цвет входящего и исходящего сообщения, цвет текста и прочитанного статуса в двух режимах. Пользователь выбирает целый пресет; изменение применяется сразу. Свободного смешивания фона и баблов нет.

В каталоге 21 вариант: стандартная тема и 20 авторских. UI представляет их одной непрерывной вертикальной сеткой из трёх адаптивных колонок, включая стандартную. Логические группы в данных нужны для типа фона, а не для отдельных карточек-разделов или горизонтальной прокрутки. Предпросмотр сверху использует реальные компоненты сообщений. Выделение плитки — одна обводка и галочка. На live-плитках слева сверху находится компактный бейдж: `LIVE · фото`, пока есть только постер; `LIVE`, когда есть настоящий видеоклип.

Общая тема приложения (`light`/`dark`/`auto`) и тема чата — разные настройки. Системная тема следует настройке ОС. Стандартные чаты наследуют брендовые токены ERG/Integra; кастомный пресет меняет только поверхности сообщений и фон. Шапка и базовый фон настроек сохраняют принятый вид прототипа. Карточка профиля здесь не добавляется.

## 3. Каноническая схема

Каждая запись `CHAT_PRESETS` неизменяема (`Object.freeze`). Поля:

| Поле | Значение/правило |
|---|---|
| `id` | Стабильный уникальный ID, например `art-coast`; не зависит от локализованного названия |
| `name` | Человекочитаемое имя |
| `group` | `standard`, `gradient`, `pattern`, `art`, `live` — тип рендеринга |
| `wallpaper` | ID пресета; только у `standard` — `plain` |
| `incoming`, `outgoing` | Производные ID вида `<id>-in/out`; у standard — `default` |
| `palette` | Для standard — `null`; для остальных — пара баблов и тематический read-цвет |
| `palette.incoming/outgoing` | `{ light, dark, ink, darkInk }`, непрозрачные hex-цвета |
| `palette.read` | `{ light, dark }`: цвет прочитанного статуса, согласованный с исходящим баблом |
| `pattern` | Производное `group === 'pattern'` |
| `poster` | `/img/chat-themes/<id>.webp` или `null` |
| `video` | Проверенный URL настоящего клипа или `null` |

`appearanceStyle()` выдаёт только переменные `--chat-*`: светлый/тёмный фон и текст обоих баблов, `--chat-status-read-light/dark`. Не добавляйте сюда глобальные брендовые токены. `appearanceClass()` выводит классы из канонического пресета, а не из неподтверждённых полей сохранённого объекта. Производный `motion` равен наличию `video`, не отдельной пользовательской настройке.

Вызовы вне React:

```js
const appearance = resolveChatAppearance(preferences, companyId);
const next = patchChatAppearance(preferences, companyId, { preset: 'art-coast' });
const theme = getChatPreset('art-coast');
```

В компоненте используйте `useChatAppearance()` и `update({ preset: id })`. Не вызывайте запись localStorage напрямую.

Формат сохранения:

```json
{
  "chatAppearance": {
    "erg": { "preset": "art-coast" },
    "integra": { "preset": "grad-mint" }
  }
}
```

Тема синхронно применяется и сохраняется в браузере. Это ещё не серверный API. Выбранное пространство хранится отдельно в sessionStorage (`qollab.company`); внешний вид пространства — в localStorage. Остальные предпочтения сохраняются при обновлении пресета.

## 4. Миграция и совместимость

1. Известный сохранённый `preset` имеет приоритет над любыми старыми цветами, wallpaper, pattern, palette и video.
2. Если `wallpaper` уже совпадает с новым ID, он становится пресетом.
3. Старый wallpaper сопоставляется с ближайшей визуальной семьёй через `LEGACY_WALLPAPERS`; старые ID — через `LEGACY_PRESETS`.
4. Старое глобальное поле wallpaper относится только к ERG. Его нельзя переносить в Integra.
5. Неизвестное или повреждённое значение даёт standard. Явно выбранный standard побеждает старый глобальный фон.
6. `patchChatAppearance()` принимает только известный ID и корректный companyId; изменения независимых цветов/движения игнорируются. Объекты входных данных не мутируются.

Примеры: `sand → grad-sunset`, `botanical → pattern-garden`, `dunes → art-fields`, `aurora-live → live-prism`, `silk-live → live-poppies`, `tide-live → live-coast`. Полная таблица живёт в коде. При переименовании/удалении ID сначала добавьте детерминированную миграцию и тест. Старые маршруты `/settings/bubbles` и `/settings/wallpaper` перенаправляются на `/settings/chat-theme`.

## 5. Цвет, геометрия и состояния сообщений

Входящий и исходящий баблы непрозрачны: фотография не меняет читаемость текста. Светлые и тёмные цвета задаются явно. Текст обычного размера и существенные метаданные должны выдерживать контраст 4.5:1; значимые графические элементы — 3:1. Проверяйте фактически вычисленные цвета, включая альфа-смешивание и `color-mix`, а не только hex из каталога.

Тематический цвет прочитанного статуса задаётся отдельно для каждого пресета и режима в READ_COLORS; фабрика добавляет его как palette.read. Не забудьте запись READ_COLORS при добавлении пресета. Standard использует брендовый read-акцент. Отправляется/отправлено/доставлено остаются нейтральными; ошибка имеет своё обозначение. Не используйте широкие правила вида `.msg-time-row svg { color: inherit }`: они стирают различие статусов. Цвет должен сохраняться в тексте, голосовом, документе, медиа с вынесенным временем и portal-превью long tap.

Край бабла — тонкая внутренняя линия на основе его собственного фона: 94% заливки + 6% чёрного, без тени и без изменения размера контента. Таймстампы, quote, link preview, профиль, waveform, подписи файлов, чужие/свои реакции проверяются отдельно. Не переопределяйте геометрию `Message` ради одного настроечного превью.

Долгое нажатие, контекстное меню мышью и клавиша ContextMenu/Shift+F10 должны показывать тот же выбранный бабл. Portal не наследует CSS-переменные от исходного DOM-родителя автоматически: переносите вычисленный контекст в общий MobileMessageMenu и проверяйте его после смены темы/пространства. Каталог визуальных состояний не заменяет проверку настоящих действий в AppRoutes.

## 6. Добавление темы

1. Выберите стабильный ID и тип; запишите композицию, название, происхождение и оба режима палитры.
2. Добавьте запись в `CHAT_PRESETS` через текущие фабрики. Сначала прочитайте их актуальные сигнатуры; не копируйте устаревший пример вызова.
3. Для CSS-фона добавьте `.qa-wall-<id>` в ChatAppearance.css. Для bitmap разместите WebP в public/img/chat-themes с тем же ID. Не вставляйте растровую картинку как data URL в JSX.
4. Подберите пару баблов, ink/darkInk и `palette.read.light/dark`; проверьте все типы сообщений. Фон не должен конкурировать с текстом.
5. Для нового seamless-паттерна используйте существующий генератор `scripts/assets/create-chat-patterns.mjs` и тонкие Phosphor-мотивы. Текущий тайл 288×336; элементы на границах повторяются с противоположной стороны. Проверяйте стык по X/Y при масштабе чата и миниатюры.
6. Обновите локализацию в действующем механизме i18n, тест количества/ID и ассетный manifest. Стабильные ID не переводятся.
7. Пройдите модель, цветовой аудит, UI-матрицу, сборку и публикационную проверку, если выпуск входит в запрос.

При исправлении существующей темы сохраняйте ID и имя ассета, если пользовательский выбор должен остаться прежним. Не меняйте текущую тему всем пользователям через случайный новый default.

## 7. Ассеты и живые фоны

Градиенты реализованы в CSS. Пять SVG-паттернов — `pattern-day/orbit/garden/travel/play.svg`. Иллюстрации — `art-coast/alpine/cabin/lighthouse/fields.webp`. Постеры будущих live-фонов — `live-coast/lake/earth/prism/poppies.webp`. Все эти пути находятся в `public/img/chat-themes/`.

Пять новых оригинальных live-изображений созданы встроенной генерацией; PNG сохранены в `artifacts/live-wallpapers-v7-2026-11-17/originals/`. WebP имеют ширину 768, размер 768×1365 и весят примерно 34–181 КБ каждый. Не используйте сжатый WebP как исходник image-to-video при наличии PNG. Промпты и происхождение — в `docs/chat-live-wallpaper-prompts.txt` и manifest.json в той же папке артефактов. ZIP `chat-live-wallpaper-sources-and-prompts.zip` содержит 5 PNG и 10 промптов. Исходники иллюстраций — `artifacts/settings-redesign-2026-11-17/v7/art-generation/`.

Сейчас все пять live-тем — статичные постеры, `video: null`. Не обещайте движение и не имитируйте его CSS-зумом. Общий ChatWallpaper готов принять реальный клип: muted, loop, playsInline, metadata preload; в миниатюре остаётся картинка. При reduced motion и скрытой вкладке видео приостанавливается; ошибка загрузки оставляет постер. Отказ autoplay не должен блокировать чат.

Пайплайн подключения видео:

1. Пользователь генерирует 10-секундный вертикальный 9:16 клип из исходного PNG, 24 fps, без звука, с неподвижной камерой. Движение локальное и спокойное: вода, трава, свет. Промпты даны отдельно для каждой сцены.
2. Получите исходный файл; проверьте длительность, частоту кадров, ориентацию, отсутствие аудио, артефактов, morphing, мерцания и смены экспозиции. Совпадение первого/последнего кадра не гарантирует совпадение скорости.
3. Подберите циклический участок/стык без рывка. Не используйте механический reverse для волн. Посмотрите минимум три повтора на телефоне; отдельно оцените границу цикла и скорость объектов.
4. Сожмите копию, сохранив оригинал: совместимый MP4/H.264, yuv420p, faststart, без аудио, разумная ширина 720–768. Размер выбирайте по визуальному качеству и устройствам; ориентир нескольких МБ не заменяет измерение.
5. Запишите реальный путь в `video`, сохраните прежний poster и ID. Обновите тест, который сейчас намеренно ожидает `video: null` у всего каталога. Проверьте fallback, reduced motion, hidden/resume, autoplay, несколько переходов между темами и потребление памяти.
6. Зафиксируйте длительность, размер, кодек, проверку стыка и устройства в manifest/handoff. Только после этого бейдж становится `LIVE`.

Обещание промпта «loop» не является проверкой готового клипа. Сеть, декодер, low-power mode и реальный WebView требуют отдельной проверки; браузерный прототип их не сертифицирует.

## 8. Происхождение и лицензии

Иллюстрации и постеры — новые сгенерированные композиции; пользовательские референсы использовались как визуальное направление. Не описывайте их как загруженные стоковые фото, копии конкретных снимков или гарантированно эксклюзивные изображения. Сохраняйте prompt/manifest и оригиналы при передаче.

Иконки интерфейса и мотивы SVG-паттернов происходят из `@phosphor-icons/react`, MIT, Copyright (c) 2020 Phosphor Icons. Точный текст находится в `node_modules/@phosphor-icons/react/LICENSE`; при переносе SVG/иконок в отдельный продукт включите этот copyright и MIT permission notice в third-party notices. Если добавляется внешний ассет, фиксируйте его источник, лицензию и необходимые атрибуции до публикации.

## 9. Проверки и выпуск

Из корня checkout с установленными зависимостями (Node ^20.19 или >=22.12):

```sh
node --test src/utils/chatThemeCatalog.test.js src/components/MessageDeliveryStatus.test.mjs src/components/messageMenuClone.test.js src/components/messageMenuActions.test.js
node scripts/check-settings-colors.mjs artifacts/settings-redesign-2026-11-17/v8
npx oxlint src/utils/chatThemeCatalog.js src/utils/chatThemeCatalog.test.js src/utils/chatAppearance.js src/components/ChatWallpaper.jsx src/components/Message.jsx src/components/MessageDeliveryStatus.jsx src/utils/messageDelivery.js src/components/messageMenuClone.js src/components/messageMenuActions.js src/components/MobileMessageMenu.jsx src/components/SettingsChatPreview.jsx src/screens/SettingsChatThemes.jsx src/screens/ChatRoom.jsx src/screens/DMChat.jsx
npm run build:all
```

Модельные тесты проверяют каталог, миграцию, базовые контрасты, семантику доставки, перенос темы в portal-копию и доступность действий меню. Второй выполняет аналитический аудит CSS и сохраняет результаты с хешами исходников. Это не screenshot-тест и не проверка браузерного layout. При изменении версии укажите новую папку вывода: default старого скрипта может указывать на v7. При расширении каталога обновите ожидаемое количество вариантов, а не удаляйте проверки.

Минимальный визуальный проход: все пресеты в ERG/Integra × light/dark; системная тема; standard/reset; сохранение после reload; узкая ширина 320 и основная 393; текст, время, 5 состояний доставки, фото, видео, голос, документ, цитата, ссылка, профиль и реакции; long tap с тем же фоном/баблом; keyboard/focus и reduced motion. В actions-стенде пройдите ответ, реакцию, копирование, пересылку, выбор и закрытие меню. Проверяйте обратную навигацию и отсутствие горизонтального overflow.

`npm run build:all` собирает приложение и Storybook и помещает Storybook в dist/storybook. Для разработки: `npm run dev`; компоненты: `npm run storybook`. Авторизованный выпуск направляется в уже существующий Worker `qollab` из `wrangler.jsonc` командой `npx wrangler deploy`. Перед публикацией проверяют точный набор изменений/commit, после — публичные маршруты, загрузку ассетов и консоль. Запишите commit, deployment ID, дату, проверки и реальные ограничения в handoff. Не называйте работу опубликованной по одному успешному build.

Контракт статической раздачи в `wrangler.jsonc` задаётся явно:

```json
{
  "assets": {
    "directory": "./dist",
    "html_handling": "auto-trailing-slash",
    "not_found_handling": "single-page-application"
  }
}
```

Cloudflare описывает auto-trailing-slash как режим, в котором index.html вложенной папки обслуживается по URL с завершающим слешем. См. [официальное описание HTML handling](https://developers.cloudflare.com/workers/static-assets/routing/advanced/html-handling/). В v8 после явной настройки проверен `/storybook/` и реальный iframe истории, а SPA deep links сохранены. Ранее `/storybook/` показывал приложение; точная причина поведения без явного значения не установлена. Сохраняйте проверенную конфигурацию и проверяйте обе точки входа после deploy, а не только наличие dist/storybook/index.html.
