# Темы чатов qollab: руководство по изменению

Актуальный контракт редизайна v9, 17 ноября 2026. Документ предназначен разработчикам и AI-агентам. Статус проверки и публикации вынесен в [handoff](chat-themes-handoff.md): описание целевого поведения само по себе не означает, что оно проверено на устройстве.

## 1. Продуктовый контракт

Тема чата — готовая согласованная композиция: фон, цвет входящего и исходящего сообщения, цвет текста и прочитанного статуса внутри бабла в двух режимах. Панели меню, экран прочитавших и список чатов используют фирменные цвета приложения и не наследуют read-цвет пресета. Пользователь выбирает целый пресет; изменение применяется сразу. Свободного смешивания фона и баблов нет.

В каталоге 21 вариант: стандартная тема и 20 авторских. Предпросмотр и каталог объединены в одну белую секцию. В ней — одна непрерывная вертикальная сетка из трёх адаптивных колонок, включая стандартную; все плитки имеют пропорции 9:16. Логические группы в данных нужны для типа фона, а не для отдельных карточек-разделов или горизонтальной прокрутки. Предпросмотр сверху использует реальные компоненты сообщений: время и receipt находятся внутри каждого бабла. Выделение плитки — одна обводка и галочка. На live-плитках слева сверху находится компактный бейдж: `LIVE · фото`, пока есть только постер; `LIVE`, когда есть настоящий видеоклип.

Общая тема приложения (`light`/`dark`/`auto`) и тема чата — разные настройки. Системная тема следует настройке ОС. Стандартные чаты наследуют брендовые токены ERG/Integra; кастомный пресет меняет только поверхности сообщений и фон. Шапка и базовый фон настроек сохраняют принятый вид прототипа. Карточка профиля здесь не добавляется.

## 1.1. Экран оформления, реакции и очистка

Три карточки темы приложения (Светлая / Тёмная / Системная) имеют одинаковые миниатюры 9:16, одинаковое внутреннее поле и равные интервалы. Это отдельный переключатель приложения, не выбор темы чата.

Быстрая реакция содержит 40 курируемых эмодзи без поля поиска. Свёрнутый вариант показывает 8: если текущего выбора нет среди первых восьми, он занимает восьмое место. Раскрытый показывает весь набор. Кнопка имеет `aria-expanded`, `aria-controls` и шеврон вниз/вверх; выбранное значение обозначено `aria-pressed`. Исходный ориентир частотности — [Unicode Emoji Frequency](https://www.unicode.org/emoji/frequency.html), где опубликована агрегированная медианная частотность из нескольких источников. Порядок и рабочие дополнения в приложении отобраны вручную: это не измерения ERG/Integra и не заявленный рейтинг за 2026 год.

Очистка кэша монтируется через общий Portal в DeviceHost и перекрывает весь экран устройства, включая шапку. Фон сильно размыт (26 px) и затемнён; отдельной центральной карточки нет. Кольцо, частицы, центральный знак, итоговая галочка и кнопка происходят от `--color-primary` текущего пространства. Категорийная палитра диаграммы кэша при этом сохраняет свой смысл. Во время процесса фон inert, фокус ограничен диалогом; после завершения фокус переходит на «Отлично», закрытие восстанавливает его. Escape закрывает только завершённое состояние; API не обещает отмены текущей операции. Reduced motion убирает орбиты, частицы и переходы. Сам job остаётся демо с таймером, не файловым удалением.

## 3. Каноническая схема

Каждая запись `CHAT_PRESETS` неизменяема (`Object.freeze`). Поля:

| Поле | Значение/правило |
|---|---|
| `id` | Стабильный уникальный ID, например `art-coast`; не зависит от локализованного названия |
| `name` | Человекочитаемое имя |
| `group` | `standard`, `gradient`, `pattern`, `art`, `live` — тип рендеринга |
| `wallpaper` | ID пресета; только у `standard` — `plain` |
| `incoming`, `outgoing` | Производные ID вида `<id>-in/out`; у standard — `default` |
| `palette` | Для standard — `null`; для остальных — пара баблов и тематический read-цвет |
| `palette.incoming/outgoing` | `{ light, dark, ink, darkInk }`, непрозрачные hex-цвета |
| `palette.read` | `{ light, dark }`: цвет прочитанного статуса внутри бабла, согласованный с исходящим баблом |
| `pattern` | Производное `group === 'pattern'` |
| `poster` | Канонический путь WebP или `null`; не вычислять по ID: live-lake → live-steppe.webp |
| `video` | Проверенный URL настоящего клипа или `null` |

`appearanceStyle()` выдаёт только переменные `--chat-*`: светлый/тёмный фон и текст обоих баблов, `--chat-status-read-light/dark`. Не добавляйте сюда глобальные брендовые токены и не передавайте эти значения на корень панели меню/activity. Для внешних индикаторов используется `MessageDeliveryStatus scope="app"`. `appearanceClass()` выводит классы из канонического пресета, а не из неподтверждённых полей сохранённого объекта. Производный `motion` равен наличию `video`, не отдельной пользовательской настройке.

Вызовы вне React:

```js
const appearance = resolveChatAppearance(preferences, companyId);
const next = patchChatAppearance(preferences, companyId, { preset: 'art-coast' });
const theme = getChatPreset('art-coast');
```

В компоненте используйте `useChatAppearance()` и `update({ preset: id })`. Не вызывайте запись localStorage напрямую.

Формат сохранения:

```json
{
  "chatAppearance": {
    "erg": { "preset": "art-coast" },
    "integra": { "preset": "grad-mint" }
  }
}
```

Тема синхронно применяется и сохраняется в браузере. Это ещё не серверный API. Выбранное пространство хранится отдельно в sessionStorage (`qollab.company`); внешний вид пространства — в localStorage. Остальные предпочтения сохраняются при обновлении пресета.

## 4. Миграция и совместимость

1. Известный сохранённый `preset` имеет приоритет над любыми старыми цветами, wallpaper, pattern, palette и video.
2. Если `wallpaper` уже совпадает с новым ID, он становится пресетом.
3. Старый wallpaper сопоставляется с ближайшей визуальной семьёй через `LEGACY_WALLPAPERS`; старые ID — через `LEGACY_PRESETS`.
4. Старое глобальное поле wallpaper относится только к ERG. Его нельзя переносить в Integra.
5. Неизвестное или повреждённое значение даёт standard. Явно выбранный standard побеждает старый глобальный фон.
6. `patchChatAppearance()` принимает только известный ID и корректный companyId; изменения независимых цветов/движения игнорируются. Объекты входных данных не мутируются.

Примеры: `sand → grad-sunset`, `botanical → pattern-garden`, `dunes → art-fields`, `aurora-live → live-prism`, `silk-live → live-poppies`, `tide-live → live-coast`. Полная таблица живёт в коде. При переименовании/удалении ID сначала добавьте детерминированную миграцию и тест. В v9 у `live-lake` изменены название на «Ночная степь», постер на `/img/chat-themes/live-steppe.webp` и согласованная палитра; ID сохранён, поэтому уже выбранная тема обновляется без сброса. Старые lake-файлы остаются историческими/совместимыми, но каталог их больше не выбирает.

Старые маршруты `/settings/bubbles` и `/settings/wallpaper` перенаправляются на `/settings/chat-theme`.

## 5. Цвет, геометрия и состояния сообщений

Входящий и исходящий баблы непрозрачны: фотография не меняет читаемость текста. Светлые и тёмные цвета задаются явно. Текст обычного размера и существенные метаданные должны выдерживать контраст 4.5:1; значимые графические элементы — 3:1. Проверяйте фактически вычисленные цвета, включая альфа-смешивание и `color-mix`, а не только hex из каталога.

Тематический цвет прочитанного статуса задаётся для каждого пресета и режима в READ_COLORS; фабрика добавляет его как palette.read. Не забудьте READ_COLORS при добавлении пресета. Standard использует брендовый read-акцент. Sending/sent/delivered остаются нейтральными, failed имеет собственное обозначение. Не перекрашивайте все SVG общим правилом: это стирает семантику статусов.

Время и receipt располагаются **внутри каждого бабла**: текст, фото/видео с подписью и без, голос, документ, профиль, цитата, ссылка. Медиа получают собственный внутренний footer, а не отдельную строку времени снаружи. Проверяйте положение относительно фактических границ бабла, отсутствие наложения на текст, переносы и доступность.

Край бабла — тонкая внутренняя линия на основе его собственного фона: 94% заливки + 6% чёрного, без тени и изменения размера контента. Quote, link preview, waveform, подписи файлов, свои/чужие реакции и внутренние метаданные проверяются отдельно. Не создавайте особую геометрию Message только для настроечного превью.

Долгое нажатие, contextmenu и ContextMenu/Shift+F10 показывают точную копию выбранного бабла. `mountMessageMenuClone()` переносит вычисленный контекст и ширину **внутрь копии сообщения**. Панели действий, emoji picker, summary/list прочитавших и список чатов остаются в контексте приложения. Там передавайте `scope="app"` в MessageDeliveryStatus; read берётся из фирменных значений ERG/Integra и не меняется вслед за пресетом. Не восстанавливайте удалённый перенос read-переменных на весь MobileMessageMenu. Каталог визуальных состояний не заменяет проверку настоящих действий AppRoutes.

## 6. Добавление темы

1. Выберите стабильный ID и тип; запишите композицию, название, происхождение и оба режима палитры.
2. Добавьте запись в `CHAT_PRESETS` через текущие фабрики. Сначала прочитайте их актуальные сигнатуры; не копируйте устаревший пример вызова.
3. Для CSS-фона добавьте `.qa-wall-<id>` в ChatAppearance.css. Для bitmap разместите WebP в public/img/chat-themes и явно задайте путь poster в каталоге; имя обычно совпадает с ID, но не обязано. Не вставляйте растровую картинку как data URL в JSX.
4. Подберите пару баблов, ink/darkInk и `palette.read.light/dark`; проверьте все типы сообщений. Фон не должен конкурировать с текстом.
5. Для нового seamless-паттерна используйте существующий генератор `scripts/assets/create-chat-patterns.mjs` и тонкие Phosphor-мотивы. Текущий тайл 288×336; элементы на границах повторяются с противоположной стороны. Проверяйте стык по X/Y при масштабе чата и миниатюры.
6. Обновите локализацию в действующем механизме i18n, тест количества/ID и ассетный manifest. Стабильные ID не переводятся.
7. Пройдите модель, цветовой аудит, UI-матрицу, сборку и публикационную проверку, если выпуск входит в запрос.

При исправлении существующей темы сохраняйте ID, если пользовательский выбор должен остаться прежним. Новый путь ассета задавайте атомарно через канонический poster; live-lake → live-steppe.webp — намеренный пример такого обновления. Не меняйте текущую тему всем пользователям через случайный новый default.

## 7. Ассеты и живые фоны

Градиенты реализованы в CSS и используют **пять разных** SVG-текстур: `grain-horizon.svg`, `grain-sunset.svg`, `grain-sage.svg`, `grain-mint.svg`, `grain-coast.svg`. Частота/октавы/контраст и размеры отличаются; выбор задают `--qa-grain-image/size/opacity` у каждой темы. Не заменяйте их одной общей текстурой. В миниатюре применяется тот же файл с масштабом 0.7.

Пять doodle-паттернов — `pattern-day/orbit/garden/travel/play.svg`; это отдельный тип фона. Иллюстрации — `art-coast/alpine/cabin/lighthouse/fields.webp`. Текущие live-постеры — `live-coast.webp`, **`live-steppe.webp` для ID live-lake**, `live-earth.webp`, `live-prism.webp`, `live-poppies.webp`. Все runtime-пути находятся в public/img/chat-themes.

«Ночная степь» — новый оригинальный кадр Млечного Пути над равнинной степью. PNG: `artifacts/live-wallpapers-v9-2026-11-17/originals/live-steppe.png`; manifest в той же папке хранит prompts, размеры и хеши. Постер 768×1365, 253 868 байт. Актуальные image и 10-second image-to-video prompts — [chat-live-steppe-prompts.txt](chat-live-steppe-prompts.txt). Для остальных четырёх live-сцен сохраняются v7-оригиналы. [Общий набор из 10 промптов](chat-live-wallpaper-prompts.txt) уже обновлён под v9: во втором разделе находится Ночная степь вместо озера. Отдельный steppe-документ содержит подробные параметры и запасной вариант с неподвижными звёздами.

Исходники иллюстраций — artifacts/settings-redesign-2026-11-17/v7/art-generation. ZIP с пятью v7 live-PNG остаётся историческим пакетом и содержит прежнее озеро. Не заменяйте исходный PNG сжатым WebP при генерации видео. Новый итоговый пакет выпуска описывается только после фактической сборки.

Сейчас все пять live-тем — статичные постеры, `video: null`. Не обещайте движение и не имитируйте его CSS-зумом. Общий ChatWallpaper готов принять реальный клип: muted, loop, playsInline, metadata preload; в миниатюре остаётся картинка. При reduced motion и скрытой вкладке видео приостанавливается; ошибка загрузки оставляет постер. Отказ autoplay не должен блокировать чат.

Пайплайн подключения видео:

1. Пользователь генерирует 10-секундный вертикальный 9:16 клип из исходного PNG, 24 fps, без звука, с неподвижной камерой. Движение локальное и спокойное: вода, трава, свет. Промпты даны отдельно для каждой сцены.
2. Получите исходный файл; проверьте длительность, частоту кадров, ориентацию, отсутствие аудио, артефактов, morphing, мерцания и смены экспозиции. Совпадение первого/последнего кадра не гарантирует совпадение скорости.
3. Подберите циклический участок/стык без рывка. Не используйте механический reverse для волн. Посмотрите минимум три повтора на телефоне; отдельно оцените границу цикла и скорость объектов.
4. Сожмите копию, сохранив оригинал: совместимый MP4/H.264, yuv420p, faststart, без аудио, разумная ширина 720–768. Размер выбирайте по визуальному качеству и устройствам; ориентир нескольких МБ не заменяет измерение.
5. Запишите реальный путь в `video`, сохраните прежний poster и ID. Обновите тест, который сейчас намеренно ожидает `video: null` у всего каталога. Проверьте fallback, reduced motion, hidden/resume, autoplay, несколько переходов между темами и потребление памяти.
6. Зафиксируйте длительность, размер, кодек, проверку стыка и устройства в manifest/handoff. Только после этого бейдж становится `LIVE`.

Обещание промпта «loop» не является проверкой готового клипа. Сеть, декодер, low-power mode и реальный WebView требуют отдельной проверки; браузерный прототип их не сертифицирует.

## 8. Происхождение и лицензии

Иллюстрации и постеры — новые сгенерированные композиции; пользовательские референсы использовались как визуальное направление. Не описывайте их как загруженные стоковые фото, копии конкретных снимков или гарантированно эксклюзивные изображения. Сохраняйте prompt/manifest и оригиналы при передаче.

Иконки интерфейса и мотивы SVG-паттернов происходят из `@phosphor-icons/react`, MIT, Copyright (c) 2020 Phosphor Icons. Точный текст находится в `node_modules/@phosphor-icons/react/LICENSE`; при переносе SVG/иконок в отдельный продукт включите этот copyright и MIT permission notice в third-party notices. Если добавляется внешний ассет, фиксируйте его источник, лицензию и необходимые атрибуции до публикации.

`npm run build:all` собирает приложение и Storybook и помещает Storybook в dist/storybook. Для разработки: `npm run dev`; компоненты: `npm run storybook`. Авторизованный выпуск направляется в уже существующий Worker `qollab` из `wrangler.jsonc` командой `npx wrangler deploy`. Перед публикацией проверяют точный набор изменений/commit, после — публичные маршруты, загрузку ассетов и консоль. Запишите commit, deployment ID, дату, проверки и реальные ограничения в handoff. Не называйте работу опубликованной по одному успешному build.

Контракт статической раздачи в `wrangler.jsonc` задаётся явно:

```json
{
  "assets": {
    "directory": "./dist",
    "html_handling": "auto-trailing-slash",
    "not_found_handling": "single-page-application"
  }
}
```

Cloudflare описывает auto-trailing-slash как режим, в котором index.html вложенной папки обслуживается по URL с завершающим слешем. См. [официальное описание HTML handling](https://developers.cloudflare.com/workers/static-assets/routing/advanced/html-handling/). В v8 после явной настройки проверен `/storybook/` и реальный iframe истории, а SPA deep links сохранены. Ранее `/storybook/` показывал приложение; точная причина поведения без явного значения не установлена. Сохраняйте проверенную конфигурацию и проверяйте обе точки входа после deploy, а не только наличие dist/storybook/index.html.
