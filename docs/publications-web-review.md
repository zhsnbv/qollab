## Исправление прокрутки

После сообщения пользователя воспроизведено: жест колёсиком оставлял `scrollY=0`, хотя контент был выше окна. Причина — `body` с `overflow:auto`, унаследованным `overscroll-behavior:none` и высотой по контенту перехватывал прокрутку перед корневым скроллером. Только для `.publications-web-review` оставлен один скроллер документа, у `body` восстановлены `overflow:visible` и `overscroll-behavior:auto`.

Проверено реальными жестами: лента Chrome 0→721 px; встроенный браузер 0→769 px; форма новости 0→379.5 px и обратно до 0 после открытия и закрытия диалога Vimeo. Мобильные стили не изменялись.

### 2026-10-12 — плавающий помощник для полной статьи

- Старый модальный AI-редактор и его кнопка внутри BlockNote удалены. В формах новости, обхода и проекта теперь один сворачиваемый чат справа снизу.
- Использован `bot-avatars` 0.2.2 (MIT), оранжевый hexagon с glossy plastic shading из локального референса `hud-motion-gallery.html`, блок 34. Состояния: ожидание/наведение, работа, сон; библиотека учитывает reduced motion.
- Принимает PDF с текстовым слоем (до 40 страниц), DOCX, TXT/MD/CSV/JSON и PNG/JPEG/WebP. До 5 файлов, по 10 МБ; извлечение текста на клиенте через PDF.js и Mammoth. Скан без текста не выдаётся за прочитанный, OCR не подключён.
- Фото из чата переносятся в отдельный блок медиа при применении статьи, не в WYSIWYG. Модель текстовая: фото не отправляются на анализ. Для обходов обязательные подписи по-прежнему проверяет форма.
- Помощник готовит заголовок, лид, BlockNote body для новости/обхода, шесть разделов проекта, а также допустимые поля предприятия/участников/оценки/эффекта по источнику. Системные настройки публикации сохраняются. Значения не из справочников отбрасываются; нехватка сведений показывается в предупреждениях.
- Живая демонстрационная интеграция: AI Horde, анонимный доступ, поддерживаемые открытые Gemma 4 / Gemma 3 / Qwen 2.5. Модель выбирается среди доступных; лимит бесплатного ответа 512 токенов обходится продолжением одного ответа (до шести частей), без выдачи незавершённого JSON за готовую статью. В UI не попадают служебные рассуждения. Очередь, остановка, таймаут и ошибки обрабатываются явно. Фиктивного fallback-ответа нет.
- Перед отправкой видна пометка о публичном провайдере. Лимит исходного контекста демо — 12 000 символов; переполнение отклоняется без обрезки. Для production нужен корпоративный backend/provider, серверная история и соответствующий контроль доступа.
- Можно уточнять запрос сообщениями, просматривать варианты, применять всю статью и отменять последнее применение. При ручных изменениях после генерации требуется явное подтверждение замены. Программное заполнение использует `setFieldValue`, чтобы заменять документы целиком и очищать старые ошибки валидации.
- Переписка, источники и варианты хранятся отдельно для каждой статьи в IndexedDB; `assistantId` переносится из новой формы в сохранённую публикацию. После перезагрузки и повторного редактирования история восстанавливается. Публикация по-прежнему выполняется штатной кнопкой формы, помощник самостоятельно её не публикует.
- Помощник поднимается над нижними действиями формы, чтобы не закрывать кнопки создания/предпросмотра; иконки Fluent, скругления и палитра Qollab сохранены.
